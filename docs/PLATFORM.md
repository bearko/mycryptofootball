# bearko.games の共通基盤とのつなぎ

My Crypto Football は、bearko.games の共通基盤（共通ログイン・アチーブメント・総合スコア・RTA・全体チャット・分析）に参加する。
共通基盤の側の手順は bearko/MyCryptoPortfolio の `docs/INTEGRATION.md`（3 章）と `sdk/v1.js` の先頭のコメント。

- タイトル ID：`football`　ホスト：`football.bearko.games`
- 窓口：`src/ui/platform.ts`。ほかのファイルは `window.BearkoGames` を触らず、ここの関数だけを呼ぶ
- SDK：`index.html` の `<head>` で `https://bearko.games/sdk/v1.js` を読む（ゲーム本体の module より前）

## 守ること

- **SDK が読めない・通信に失敗しても、最後まで遊べる**。窓口の呼び出しは全部 try/catch で包み、失敗は `console.warn` だけ（`tests/platform.test.ts` が確かめる）
- ゲームは Cookie を触らない。ログイン状態は共通基盤が持つ
- 外部の解析タグや自前のプレイログは入れない。数は共通基盤の管理画面で見る
- `init({ presence: false })` にしない（来訪が止まり、KPI が出なくなる）

## チュートリアルの段

はじめての人がどこで離れるかを、管理画面の「チュートリアル」タブで見るためのもの。
チュートリアルは、**タイトルの「はじめる」でつくった部の最初の 1 週間**（入部説明会から、練習試合のあとのマネージャーの最後の説明まで。`docs/GAME_DESIGN.md` の「はじめての 1 週間」）。

| 番号 | id | いつ送るか |
|---|---|---|
| 0 | `start` | タイトルの「はじめる」で新しい部をつくった（入部説明会が開いた） |
| 6 | `captain` | 説明会で最初の 1 人（主将）をえらんだ |
| 12 | `recruit_done` | 7 人を入部させて、練習グラウンドに出た |
| 18 | `policy_done` | 最初のミーティング（育成方針）を「この方針でいく」で閉じた（閉じずに練習へ進んだときは、最初の練習といっしょに） |
| 24 | `first_practice` | 最初の練習カードを出した（2 日目になった） |
| 30 | `day3` | 3 日目になった |
| 36 | `match_day` | 最初の試合の日（練習試合）になった |
| 42 | `match_start` | 最初の試合が始まった（試合の画面を開いた） |
| 48 | `first_play` | 最初の試合で、1 枚目の作戦カードを出した（筋書きではラン） |
| 54 | `second_play` | 2 枚目の作戦カードを出した（筋書きではパス） |
| 60 | `first_td` | 最初の試合で、タッチダウンを決めた（筋書きでは逆転のタッチダウン） |
| 66 | `match_done` | 最初の試合が終わった |
| 90 | `done` | チュートリアルが終わった：マネージャーの最後の説明（試合のあと）を聞きおえた。または、スキップのあと「この先の説明もいらない」を押した・最後の場面をスキップした |

- **番号と id は、公開したあとに変えない**（変えると前後の数を比べられなくなる）。足すときは空いている番号に入れる
- 送るのは `Season.guide` が立っている部の 1 年目だけ。古いセーブ・デバッグ用 URL（`?go=`・`?bot=1`）・テストでは送らない
- セーブされている内容から段を判定する（`trackGuide`。セーブのたびに呼ばれる）。セーブに残らない `captain`・`policy_done`・`first_play`・`second_play`・`first_td` は、その場で送る（`guideEvent`）
- 同じ段は 1 回だけ送る（窓口・SDK・サーバーのどれもが最初の 1 回だけ残す）
- 場面ごとのスキップ（その場面の説明だけ飛ばす）では `done` を送らない。説明をぜんぶやめたときに送る（共通基盤の決まり：飛ばせるチュートリアルは、飛ばしたときに `done`）。そのあとも遊びつづければ、着いた段は送る
- 試合でスキップすると筋書きではなくふつうの試合になるので、`first_td` は決めた人だけに付く

## 全体チャット

- `init({ chat: { layout: 'float', button: false } })`：**PC の右側のドックも、右下の 💬 も出さない**。タイトル画面の「チャット」と、設定の「チャット」から窓を開く（どちらも SDK が読めたときだけ出る）
- 理由：画面いっぱいを使う作りで（フィールド・作戦カードの手札・四すみの得点表示）、1rem が画面の大きさで決まる。幅 320px のドックが右に出ると、16:9 の PC では右の手札と設定のボタンが隠れる。💬 を置ける空いたすみもない
- 時間で進んで操作をせかす場面はないので、書いているあいだ止めることはしていない
- 通知（アチーブメントなど）は画面の上に出す（`toast: 'top'`）。下は作戦カードと練習カードの場所

## アチーブメント・総合スコア・RTA（案）

共通基盤の側に定義が足されるまでは、呼び出しの口だけがある（`unlockTrophy`・`submitScore`・`rta`）。ゲームからはまだ呼んでいない。
下は共通基盤のセッションに渡した案。決まったら「案」を外して、ここを正にする。

### アチーブメント（条件の案。名前と絵は共通基盤の側で決める）

| 仮の名前 | 条件 | 種類 |
|---|---|---|
| `first_win` | はじめて試合に勝つ（練習試合をふくむ。チュートリアルを最後まで遊ぶと取れる） | 軽い目標 |
| `club` | 同好会になる（地区大会の 1 回戦に勝つ） | 最初の節目 |
| `special_td` | 特別作戦のカードでタッチダウンを決める | 軽い目標 |
| `onside` | オンサイドキックを成功させる（負けている第 4 クォーターにだけえらべる。成功は 2 割前後） | めずらしい |
| `district` | 地区大会で優勝する | 節目 |
| `eleven` | 11 人制の試合に勝つ（県大会ではじめて勝つ） | 節目 |
| `graduate` | 卒業生をはじめて送り出す（3 年目をおえる） | 軽い目標 |
| `meimon` | 名門になる | 節目 |
| `nation` | 全国大会で優勝する | ゲームクリア |

来訪（`football.visit`）は SDK が送るので、ゲームでは作らない。

### 総合スコア（案）

- 種類：`progress`（積み上げ。部は年をまたいで続く）
- 送るもの：`{ tier, years, wins, titles: [地区, 県, 地方, 全国], nation }`
  - `tier`：これまでに届いたいちばん上の格（0 素人 〜 6 名門）　`years`：何年目か　`wins`：通算の勝ち数
  - `titles`：大会ごとの優勝回数　`nation`：全国大会で優勝したことがあるか（クリア）
- 送る時機：試合がおわるたび（`{ quiet: true }`。1 試合に数分かかるので、1 分に 1 回の上限には当たらない）と、年のおわりの画面（通知あり）
- 節目の案：同好会になる＝最初の節目、全国大会の優勝＝ゲームクリア
- 「ふつうに遊んだ」目安（ていねいに遊ぶ自動操縦 60 部）：
  - 同好会 1.3 年目、弱小 2.4 年目、注目株 4.0 年目、中堅 5.5 年目、強豪 6.8 年目、名門 9.2 年目
  - 10 年目のおわり：通算 22〜23 勝、大会の優勝 1.6 回、格は強豪〜名門
  - 全国大会の優勝：25 年で 6 割の部が達成（平均 15 年目）。地区大会の優勝は 25 年で 55%（平均 2.5 年目。早く昇格すると地区大会を卒業してしまう）
  - 1 年は練習 24 日と試合が最大 4 つ

### RTA（案）

- レギュレーション `football-district`（開部から地区大会の優勝まで）
  - 始まり：入部説明会で 7 人を入部させたとき
  - 区切り：`first_win`（最初の勝利）→ `club`（同好会）→ `district`（地区大会の優勝）
  - ゲーム内の時間：日数（1 年を 28 日として、年をまたいで数える）。`igt: 'days'` として `igtMs` の欄に入れる
  - いちばん早くて 1 年目の 28 日目（1 年目の決勝に勝つ）。自動操縦では 1 年目の優勝は 14%
- タイトルに「RTA で始める」の入口が要る（まだ無い）
